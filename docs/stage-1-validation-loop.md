# Stage 1 validation loop

Scope: existing in-memory fixtures only. No real file/process tools and no extra model instructions. Keep historical round-trip scores unchanged.

1. **Local contract, both machines.** Begin with the same source on Windows and Linux. Run `cargo fmt --check`, `cargo test --locked --offline`, and `cargo build --locked --offline`. Stop on a local failure; reproduce it without a model and add a regression before changing the implementation.
2. **Model and transport, both machines.** Run `sourceharness check-next-call 5` and `sourceharness smoke-result-page` from the checkout using each machine's existing Magpie endpoint and the same model route. Save the two evidence files. Check real call names/arguments, returned values, and the next action, not what the model says it did.
3. **Classify every failure before changing anything.** A rejected invalid call is a model input failure, not a Rust execution failure. A valid call that returns an incorrect result is an execution failure. Correct results that are paired with the wrong call ID or fail to reach the model are transport failures. A correct tool result followed by a wrong action or final reply is a model decision or delivery failure, respectively. Compare every automatic delivery failure with the model's actual reply: a known keyword-scoring false negative is a test defect, not a tool or model result. Keep automatic and audited delivery counts separate. Unknown execution outcomes must never trigger blind retries.
4. **Keep the sample honest.** Record confirmed upstream rate limiting/timeouts separately from correctness; require the upstream response or matching gateway event. Unknown failures are not excluded. Do not repeatedly rerun successful scenarios to improve a score. Refill a blocked sample at most once after the route recovers, and keep both attempts. The 40-call run is a regression screen, not a statistical certification or a replacement for the original stage gate.
5. **Fix the failing layer only, then rerun.** Reproduce against the same inputs, add the smallest independent regression, then run the same checks on both machines. Stop the cycle when local tests and pagination pass and all model failures are accounted for; if a real model issue remains, report it and do not call the stage passed or expand to real files/processes. Use a paired control and keep the request/tool contract fixed when evaluating a model-facing change.

The `check-next-call` exit code includes the original strict automatic delivery screen. Read its evidence before assigning blame. Results for service/access/status scenarios are intentionally simulated; the calculator, in-memory catalog searches, and pagination run real local logic.
